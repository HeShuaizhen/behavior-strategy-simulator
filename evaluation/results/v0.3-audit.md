# v0.2 Audit — Evidence-Based Assessment

## 1. Instructions with Strong Evaluation Support

| Instruction | Evidence | Verdict |
|------------|----------|---------|
| VOI (ask 1-3 high-impact questions) | R1+R2: Skill=2, Baseline=0 across 9 runs. Single biggest delta. | **KEEP, strengthen** |
| Fact/Assumption/Unknown separation | Never observed in baseline. Skill=2 consistently. | **KEEP** |
| Dynamic Updating (re-evaluate on new facts) | Case01 Skill runs explicitly update state each turn. | **KEEP** |
| Strategy Fragility (Low/Med/High) | Baseline=0-1, Skill=2. Structured dependency analysis absent from baseline. | **KEEP** |
| Exposure Surface | Baseline=0, Skill=2. | **KEEP** |
| Event Chain Simulation (2-5 nodes) | Baseline=1 (linear), Skill=2 (branching). | **KEEP** |
| Regret Gate (check new info first) | Case01 Turn 7: Skill classifies as FOMO, baseline re-argues. | **KEEP** |
| No fake percentages | Both=2. Ceiling effect. Base model already avoids this. | **KEEP (lightweight)** |
| Safety boundary (analyze deception, don't optimize) | Case01: Skill analyzes Narrative Debt, recommends truthful alt. | **KEEP** |

## 2. Instructions Without Evidence of Value

| Instruction | Issue |
|-------------|-------|
| Decision Profile (risk_appetite, autonomy_need, etc.) | Never activated in any evaluation. Not core to the behavioral delta. Single-turn cases can't accumulate profiles. | **DOWNGRADE to optional** |
| Preference-Neutral vs Personalized | Only testable with persistent profile. Current evaluations are all single-session. | **DOWNGRADE** |
| Full Decision State for all decisions | Case04 showed Skill doesn't need full state for simple decisions. Overhead risk. | **ADD Lite mode** |
| References loading protocol (5 files) | Models can't actually "load on demand" — they either have the content or don't. The reference structure benefits human maintainers more than runtime. | **SIMPLIFY reference model** |

## 5. Framework Dump Risk

| Risk Factor | Evidence |
|-------------|----------|
| Phase labels (Phase 1, Phase 2...) | Case01 Skill exposed these to user in R1. R2 improved but not eliminated. |
| Dimension table format | Case01 Skill showed a markdown table of dimensions to user. |
| Internal terminology in user output | "Fragility", "Exposure Surface", "Narrative Debt" appear in Skill outputs. | 

**Action:** Add explicit "Hidden Framework Rule" — translate all internal terms to natural language in user-facing output.

## 6. VOI Over-Questioning Risk

| Risk | Evidence |
|------|----------|
| VOI delay without recommendation | Case05 skill-02/03 deferred recommendation to ask 3 VOI questions. In single-turn evaluation, this means "no answer." |
| Non-blocking questions treated as blocking | Skill sometimes waits for answers that wouldn't actually flip the recommendation. |

**Action:** Add Blocking/Non-blocking VOI distinction. Always give provisional recommendation with non-blocking questions.

## 7. Theoretically Present but Practically Unexecutable

| Mechanism | Why Unexecutable |
|-----------|-----------------|
| Reference file loading (§9) | LLMs in current architectures can't dynamically load files at inference time. The reference list is documentation for humans. |
| Decision Profile accumulation across sessions | No persistence mechanism. No memory. Single-session only. |
| Outcome tracking / learning from past decisions | Same — no persistence. |
| "Load references when needed" | The model either has the content in context or doesn't. There's no lazy-loading for prompts. |

**Action:** Remove "when to read" table. Replace with: "These reference files document the methodology. Key concepts are summarized inline."
