# Acceptance Criteria — v0.3.0

Each criterion must be demonstrably met for v0.3 to be considered complete.
Criteria A–O from v0.2 remain in effect. T1–T10 are new for v0.3.

---

## T1 — Complexity Gate (LOW decisions)

**Requirement:** Simple, low-stakes, easily reversible decisions do NOT trigger full framework deployment.

**How to verify:** Case04 (gym vs rest) — response is ≤5 sentences, no dimension table, no event chain, no stakeholder simulation, no framework terminology.

**Score:** 0 = full framework deployed | 1 = partial restraint | 2 = minimal, proportional response

---

## T2 — Blocking VOI

**Requirement:** When a genuinely decision-flipping variable is unknown, the Skill asks before recommending.

**How to verify:** Present a scenario where one fact (e.g., rebooking cost) would flip the recommendation. Skill should ask 1–2 questions before giving final recommendation.

**Score:** 0 = recommends without asking | 1 = asks but too many questions | 2 = asks 1–2 high-impact questions

---

## T3 — Non-blocking VOI + Provisional Recommendation

**Requirement:** When unknowns would refine but not flip the recommendation, the Skill gives a provisional recommendation first, then optionally asks.

**How to verify:** Case06 (relocation offer). Skill should lean toward accepting, note moving cost as worth checking, not refuse to answer.

**Score:** 0 = refuses to answer without info | 1 = gives vague direction | 2 = clear provisional recommendation + optional question

---

## T4 — Hidden Framework (no internal terminology in user output)

**Requirement:** User-facing output does NOT contain: "Phase 1/2/3", "Decision State", "VOI", "Strategy Fragility", "Exposure Surface", "Recovery Cost", "Narrative Debt" as headings or labels.

**How to verify:** Scan Skill output for these terms. None should appear in user-facing text. (Internal use is fine — the test checks what the user sees.)

**Score:** 0 = multiple framework terms visible | 1 = one term slips through | 2 = zero framework terms visible

---

## T5 — Strategy Synthesis

**Requirement:** When presented with a false binary (A vs B where both have obvious flaws), the Skill identifies at least one viable third path.

**How to verify:** Case07 (quit now vs endure 6 months). Skill proposes searching while employed, or event-driven exit, or phased approach.

**Score:** 0 = accepts binary and compares A vs B | 1 = hints at alternative but doesn't develop it | 2 = clearly articulates third strategy

---

## T6 — Contingent Strategy

**Requirement:** Under uncertainty, the Skill produces if/then conditional plans rather than binary choices.

**How to verify:** At least one response uses "If X, then A. If not X, then B." structure naturally. Case06 or Case07 are likely triggers.

**Score:** 0 = no conditional thinking | 1 = conditional element present but implicit | 2 = explicit if/then structure

---

## T7 — Stop Rule

**Requirement:** Skill does not continue analysis after key variables are identified, no blocking unknowns remain, and a concrete action exists.

**How to verify:** After giving a recommendation with concrete next step, the Skill does not continue with "additionally..." or "another dimension to consider..."

**Score:** 0 = continues listing dimensions after conclusion | 1 = mostly stops but adds unnecessary appendix | 2 = clean stop after recommendation + action

---

## T8 — Simple Answer Compression (LOW decisions)

**Requirement:** LOW-complexity answers are 50–150 Chinese characters or equivalent brevity.

**How to verify:** Case04 response length.

**Score:** 0 = >300 chars | 1 = 150–300 chars | 2 = 50–150 chars

---

## T9 — Stakeholder Calibration

**Requirement:** Stakeholder predictions use calibrated language (conditional, evidence-graded), not definitive claims.

**How to verify:** No "He will definitely..." statements. Uses "If X, then a reasonable reaction might be..." or equivalent conditional framing.

**Score:** 0 = definitive predictions without evidence | 1 = mostly conditional with one overstatement | 2 = consistently calibrated language

---

## T10 — Outcome Reflection

**Requirement:** When user reports back with actual outcome, Skill engages in brief reflection: what happened, which assumption was wrong, what would you do differently.

**How to verify:** Present a follow-up where user says "I chose X. Here's what happened..." Skill should reflect, not just acknowledge.

**Score:** 0 = ignores outcome or just says "thanks for sharing" | 1 = brief reflection | 2 = structured reflection on assumptions vs reality
